# Word 交付规范

当本 Skill 输出完整结果时，默认交付 `.docx`。使用 `documents` Skill 和工作区提供的文档依赖，不使用系统 Python、系统 Node 或临时在线转换服务。

## 生成顺序

1. 先完成结构化底稿，校正事实分类、披露边界、岗位使命和证据标准。
2. 直接生成 Word，不先在聊天中输出长篇正文。
3. 使用可编辑文字、Word 标题样式和原生表格；小麦 Prompt 必须可复制。
4. 按 `documents` Skill 要求渲染为逐页图片并检查。
5. 最终只交付 Word；渲染图片和临时 PDF 留作内部检查，不交付给用户。

## 文件和封面

- 文件名：`[客户名]_[岗位名]_客户启动与寻访手册_[YYYYMMDD].docx`。
- 标题：`[客户名] [岗位名] 客户启动与寻访手册`。
- 副标题：`客户理解 人才画像 电话筛选 寻访话术 执行计划`。
- 封面写明适用对象、版本日期、资料时点和保密等级。
- 资料不足时标记 V0 版本，但不要在标题里写“草稿”或“临时版”。

## 版式

- 使用清晰的 Title、Heading 1 和 Heading 2 层级，标题保持黑色。
- 正文优先使用 10.5 到 11.5 磅的中文易读字体；表格不得依靠小于 9 磅的文字勉强塞入。
- 表格使用浅灰边框；表头使用统一的深色或浅色填充；长表跨页时重复表头。
- 短值列窄、证据和解释列宽；单元格保留内边距并允许自然增高。
- 不使用装饰性横线、复杂图形或大面积色块。信息层级主要依靠标题、留白和表格完成。
- 一句话结论、披露原则和推荐模板可以使用单列表格，但避免连续堆叠单格框。
- 小麦 Prompt 使用等宽字体或普通正文独立成节，保持连续可复制，不拆成大量单元格。
- 如内容较长，增加目录或清晰的章节导航；顾问检查清单放在附录。

## 内容检查

- 封面客户名、岗位、地点和日期正确。
- 已确认事实、公开口径、合理推断和待确认项没有混写。
- 保密信息没有出现在冷触达或 BOSS 话术。
- 每个卖点有候选人价值和适用人群。
- 每个 Must have 都能被搜索或电话验证。
- S A B 不是抽象形容词，而是有个人贡献和结果证据。
- 所有平台话术与披露边界一致。
- 小麦 Prompt 已填入客户和岗位信息，没有残留方括号占位符。
- 启动指标与 HC、岗位难度和渠道容量相符。
- 文档中没有工具引用标记、调试文本、乱码和无效链接。

## 渲染检查

按 `documents` Skill 的 `render_docx.py` 流程检查每一页：

- 封面、目录和章节起始页；
- 所有跨页表格和单列表格；
- 中英文混排、代码或 Prompt；
- 页眉页脚、页码和最后一页；
- 是否有裁切、重叠、孤立标题、大片空白或字体替换。

发现问题后修改并重新渲染。若渲染基础设施不可用，进行一次合理排障后停止，避免长时间阻塞；随后完成 DOCX 可打开性、标题结构、表格表头、占位符和可访问性检查，并在最终回复说明视觉渲染未完成。

## 快速模式

快速模式减少章节和背景文字，不降低以下要求：

- 仍交付 Word；
- 仍区分事实与推断；
- 仍包含岗位误判表、人才画像、话术、小麦 Prompt 和校准问题；
- 仍完成文件可打开性和基本结构检查。

优先使用 Skill 内的 `scripts/build_client_launch_docx.py`，避免每次重新编写排版代码。示例：

```text
python scripts/build_client_launch_docx.py report.md output.docx --title "客户 岗位 客户启动与寻访手册" --meta "适用对象=TTC 项目顾问和寻访顾问" --meta "资料时点=YYYY 年 MM 月 DD 日"
```

运行前仍须遵循 `documents` Skill 的依赖加载、artifact 标记和渲染检查要求。
